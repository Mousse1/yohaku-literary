# 余白。v3 — 作品ごとの共有URL

## 追加された機能

- 承認・公開された作品に `https://<あなたのホスト>/works/<作品UUID>` という固定URLを割り当てます。
- 「作品を探す」の各カードの「読む」は通常のリンクです。新しいタブで開く・URLをコピーする操作にも対応します。
- 作品本文の画面に「作品のURLを共有」ボタンを追加しました。対応スマートフォンでは共有メニュー、その他はクリップボードコピーを利用します。
- 作品URLを直接開いた場合でも、Supabaseからその作品だけを取得します。作品一覧の読み込み順や件数には依存しません。
- 旧版から新版への改訂後も同じURLで**最新の承認済み本文**を表示します。改訂履歴の閲覧は従来どおりです。
- 非公開・削除済み・存在しない作品への直リンクは「表示できません」と案内します。

## 公開手順

1. **GitHubの現在のコードをバックアップ**してください。既存の公開サイトとSupabaseテーブルを削除しないでください。
2. このZIPの `yohaku-public` 内のファイルを、GitHubリポジトリにある既存の `yohaku-public` の内容と置き換えます。`package.json` と `src/main.jsx` の場所を確認してください。独自変更がある場合は差分をマージしてください。
3. Cloudflare → Workers & Pages → `yohaku-literary` → Settings → Build で、**Root directoryが`package.json`のあるフォルダ**になっていることを確認します（例：`yohaku-public`）。
4. Build command: `npm run build`、Deploy command: 以前と同じ `npx wrangler deploy`、出力先は `dist` を使います。
5. **Build variables and secrets** の `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` は引き続き同じ値を使います。今回の変更によりキーを再生成する必要はありません。
6. GitHubへのコミットでデプロイが走るはずです。デプロイが成功したら、匿名ブラウザで作品URLのアクセスを確認してください。

このバージョンでは**Supabaseへの追加SQLは必要ありません**。既存のテーブルとRow Level Security (RLS) を引き続き使います。

### 実機テスト

- [ ] 未ログインでトップにアクセスできる。
- [ ] 公開作品のカードから「読む」を押すと URLが `/works/<UUID>` に変わる。
- [ ] URLをコピーして、未ログインの別ブラウザで直接開ける。
- [ ] ブラウザをリロードしても同じ作品が表示される。
- [ ] 一覧にない古い作品もURLを使って表示できる。
- [ ] 作品の「URLを共有」ボタンでURLをコピー／共有できる。
- [ ] `#mine` など既存の画面に戻れる。ブラウザの戻る操作も確認する。
- [ ] 非公開になった作品は匿名の直リンクから閲覧できない。
- [ ] 投稿者しか見られない下書きや審査中の本文が匿名ユーザーに返されない。
- [ ] 改訂後も元の作品URLが維持される。

### 注意：SNSのカード表示・検索・AIによる閲覧は別機能

このv3は**ブラウザで直接読むための共有リンク**です。Reactがブラウザ内でSupabaseから本文を読み込むため、JavaScriptを実行しないSNSクローラーや外部取得ツールには、個別のタイトル・要約・本文が見えない場合があります。また、HTMLのHTTPレスポンスは、未公開IDでもSPA共通の200レスポンスになることがあります。すべてのクローラーに正確な内容・404を提供し、SNSカードを表示したい場合は、次の段階でCloudflare Workersで作品のHTMLを**サーバー側生成**することをおすすめします。その際は必ず `status='published'` で絞り、RLSや閲覧権限を維持してください。

### 元の設定を変更しない項目

- 公開済み作品のUUID
- Supabaseプロジェクト・URL・公開用Key
- 運営者アカウントと管理者権限
- 改訂管理版v2で追加したDBテーブル・移行済みの履歴
- Cloudflare Accessの設定（すでに一般公開できている場合）

`public/_redirects` は含めていません。Workers静的アセット用の `wrangler.jsonc` の `assets.not_found_handling='single-page-application'` により、`/works/<UUID>` の直接アクセス時にもReactアプリを返す設計です。

**補足:** ZIPに同梱している既存の改訂機能用SQLは、前回提供した `yohaku-migration-fixed-20261029.sql` と同じ修正版に更新済みです。今回URLを共有するだけなら、SQLを実行し直さないでください。
