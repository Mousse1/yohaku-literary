# 余白。v6.4 — 下位作品の参考文献を親作品に集約表示

## 内容

例：「エチカ」→「第一部 神について」→「定義／公理」の「定義／公理」に3件の参考文献を登録すると、上位の「第一部 神について」と「エチカ」それぞれの個別作品ページでも3件が表示されます。登録元の階層名から原文の個別作品URLへ移動できます。

- 「作品の参考文献」と「下位作品の参考文献」を別の欄に表示します。
- 下位作品・孫作品・さらに下層の公開作品に登録された文献を、登録元ごとに表示します。
- 1作品の登録上限20件はそのまま。親側に集約表示した文献は親の登録件数には加算されません。
- 複数作品で同じ文献が登録されていれば、どの作品から来た文献か追跡できるように、それぞれ表示します。
- 非公開・審査待ち・差し戻しの作品は匿名閲覧で一切表示しません。非公開の親を経由する子の情報も表示しません。
- 読書画面だけでなく、並列読書の「参考文献・解説」パネルでも表示します。
- 改訂審査・作品URL・階層グループの構造・本文上限は変更しません。

## 更新方法

1. Supabaseをバックアップし、現在v6.3に必要なSQLが導入済みか確認してください。
2. Supabase Dashboard → SQL Editor → New query で `supabase/migrations/20261030_descendant_references.sql` の全文を一度実行します。既存の`schema.sql`を再実行しません。
3. ZIP中 `yohaku-public` にある新規 `src/DescendantReferences.jsx` と、更新済み `src/main.jsx` / `src/ParallelReader.jsx` / `src/style.css` をGitHub側へ反映します。環境変数・公開URL・認証設定はそのままです。
4. Cloudflare WorkersでGitHub連携の新しいデプロイを実行します。Build command は `npm run build`、Root directory は `package.json` と `index.html` が並ぶフォルダを指すようにします。
5. 公開済みの親子作品を用意して参考文献を子のみに登録し、親と祖父母の作品ページで反映されることを確認します。

## 動作確認例

- 親「エチカ」：参考文献0件
- 子「第一部 神について」：参考文献0件
- 孫「定義／公理」：参考文献3件
- 「第一部 神について」および「エチカ」の「下位作品の参考文献」に、登録元「定義／公理」が示された3件が出る
- 孫作品を非公開にすると親側の集約一覧から消え、再公開すると再び現れる
- いずれの投稿フォームでも参考文献は最大20件のまま

## 実装・セキュリティ

`list_descendant_references` は `security invoker` の読み取り専用関数です。匿名アクセス可能な`published`状態の作品の階層だけを再帰探索し、既存のSupabase RLSに従って文献を取得します。件数が多くてもクライアント側で400件ずつページ取得します。公開中の作品が変更された場合は、画面を再読み込みすると最新の内容が反映されます。

## 追加の注記

- 旧版の承認済み改訂履歴はその時点の文献スナップショットを保ちます。下位文献の集約は**現在公開中の下位作品**に対してのみ行うもので、過去版の文献を親へ自動追加するものではありません。
- この追加SQLは今回のマイグレーションだけを新しく実行するためのものです。Supabaseプロジェクトの新規作成や既存Keyの再発行は不要です。
- 公開環境でのDB接続・RPCの動作検証は別途必要です。SQLの設定に不備がある場合は、本文側の一覧表示はそのまま維持され、集約表示部分だけにエラーが表示されます。
