# v7.23 予約投稿の反映と使い方

## 反映
1. SupabaseのSQL Editorで、supabase/migrations/20261118_scheduled_publication.sql を最後まで実行します。v7.22の公開・非公開機能用SQLが前提です。
2. SupabaseのIntegrations → Cronで、yohaku-publish-reservations が有効になり、毎分の実行が成功することを確認します。SQL末尾でCronの有効化とジョブ登録を行います。エラーが出た場合は、Cronでpg_cronを有効にしてからSQLを再実行してください。同じ名前のジョブは更新されます。
3. ソースを更新して再デプロイします。

## 使い方
- 投稿・編集画面で「公開日時を予約する」を選び、日本時間の日時を入力して「予約を保存」を押します。1年後などの遠い日時も指定できます。
- 公開済み作品は「自分の作品」の「公開日時を予約」から設定できます。予約を保存した時点で非公開になります。
- 登録済み予約は「自分の作品」で日時変更・取り消しができます。取り消した作品は非公開で保存されます。「公開に戻す」を押すと予約を解除して公開します。
- 審査付きの作品は承認が必要です。指定日時を過ぎても未承認なら待機し、承認後に自動公開します。
- 非公開の親グループ配下は親の公開まで待機します。親と子を同時刻に予約した場合、子の公開は後続の処理になることがあります。
- 公開処理は毎分、最大100件ずつ実行します。指定時刻以降の処理で公開されるため、秒単位の一致は保証されません。
- ブラウザーを閉じていても実行されます。予約当日までSupabaseプロジェクトとCronを稼働させてください。サービス停止中は公開が遅れ、再開後に期限を過ぎた予約を処理します。

## 確認
まずテスト作品を数分後に予約し、ログアウト状態で予約前は読めず、予定時刻後に本文を読めることをご確認ください。
ローカルでは日本時間変換、1年後の予約、権限、日時変更・取消、親の非公開、承認待ち、二重実行、原稿保存の失敗時の巻き戻しを検証し、ビルドに成功しています。
